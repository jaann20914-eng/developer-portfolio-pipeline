# 소재 태그 분류표

태그는 검색과 공고 매칭을 위한 구조화 정보다. 본문에 근거가 있을 때만 선택하며, 유사어를 새로 만들지 않고 아래 목록을 우선 사용한다.

## 1. 강점 태그

- 성능·비용
- 동시성·정합성
- 장애 대응·복구
- 보안·접근권한
- 실시간·이벤트
- 비동기·상태관리
- 데이터 모델링·조회
- 외부 연동·의존성
- UI·UX 문제 해결
- 테스트·검증
- 관측·운영
- 협업·명세 조정
- AI 협업·작업 방식

## 2. 영향 태그

- 응답 지연
- 처리량·호출량
- 저장·전송 비용
- 데이터 정확성
- 권한 경계
- 가용성
- 사용자 이탈·완료 흐름
- 복구 가능성
- 유지보수성

## 3. 증거 수준

- A · 코드 + 자동 테스트 + 전후 측정
- B · 코드 + 자동 테스트 또는 재현 기록
- C · 설계 문서 + 로그·화면·커밋 중 하나
- D · 회고 또는 구두 설명만 존재

A가 항상 더 좋은 소재라는 뜻은 아니다. 공고 관련성과 직접 기여도가 우선이며, 증거 수준은 주장 강도를 조절하는 기준이다.

## 4. 기여 형태

- 직접 구현
- 공동 설계·구현
- 팀 전체 성과

직접 구현과 팀 전체 성과를 같은 항목으로 합치지 않는다.

## 5. 문제 발생 성격

- 운영 발생
- 개발 중 발견
- 테스트 재현
- 잠재 위험 분석

잠재 위험을 실제 사고처럼 표현하지 않는다.

## 6. 역할·기술 태그

역할과 기술은 프로젝트 자료에 나온 이름을 사용한다. 프레임워크 버전이 선별에 중요하지 않으면 제품명만 저장한다. 역할 태그 예시는 `백엔드`, `프론트엔드`, `풀스택`, `모바일`, `인프라`, `UI/UX`, `AI·데이터`다.

## 태그 수 제한

- 강점: 핵심 1~3개
- 영향: 핵심 1~2개
- 역할: 1~2개
- 기술: 실제 설명에 필요한 주요 기술 3~6개

태그가 많을수록 검색 정확도가 낮아지므로 “관련 있음”보다 “이 소재의 중심인가”를 기준으로 선택한다.
