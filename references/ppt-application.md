# PPT 적용 기준

## 입력

- 원본 PPTX 경로
- 승인된 페이지별 텍스트
- 페이지별 소재와 섹션 대응표
- 포트폴리오 문구 작성 기준
- 레이아웃 명세 (`design/layout-spec.md`)
- 디자인 토큰 (`design/design-tokens.md`, 현재 덱 형식이면 `design/tokens-current-deck.md`)
- 사용자가 선택한 경우에만 디자인 옵션

## 작업 모드

작업 전에 모드를 정하고, 사용자가 허용한 모드 밖의 변경은 하지 않는다. 여러 모드를 함께 쓸 수 있다.

| 모드 | 허용 범위 | 사용 조건 |
| --- | --- | --- |
| `text-only` | 승인된 텍스트만 교체. 슬라이드 수·순서·도형·이미지·색상 유지 | 기본값 |
| `rebuild-from-template` | 템플릿 슬라이드를 복제·삭제해 프로젝트 수와 트러블슈팅 수에 맞게 페이지 구성. 새 페이지는 `layout-spec.md`의 유형과 좌표를 따름 | 페이지 구성이 바뀔 때 |
| `diagram` | 도식·차트·로고를 새로 만들거나 고침 | 사용자가 도식·차트 작업을 요청할 때 |

## 공통 적용 규칙

1. 작업 전 원본의 `_수정전백업` 사본을 같은 폴더에 만든 뒤, 본 파일에 저장
2. 사용자가 PPT를 직접 고칠 수 있으므로, 수정할 때마다 최신 파일을 다시 읽고 그 위에 적용. 사용자가 고친 부분은 요청 없이 되돌리지 않음
3. 승인된 텍스트와 요청된 페이지만 변경. 저장 후 원본과 비교해 바뀐 슬라이드가 요청 범위와 같은지 확인
4. 제목, 섹션 제목, 본문, 수치 영역의 역할 유지
5. 빈 자리표시자와 `확인 필요` 제거
6. 공간이 부족하면 우선순위가 낮은 설명을 압축하고 핵심 수치와 비교 대상 유지
7. 자동 맞춤으로 글자를 줄이기 전에 문장 압축
8. `token_mode: preserve-existing`이면 기존 PPT의 글꼴·크기·굵기·간격·색상 유지
9. `active_option: none`이면 디자인 옵션을 적용하지 않음
10. 파일이 PowerPoint에 열려 있으면 저장이 실패하거나 열린 창이 나중에 덮어쓸 수 있음. 저장 전에 사용자에게 저장하지 말고 닫도록 안내

## 텍스트 상자 규칙

- 텍스트 상자 안쪽 여백 0, 위쪽 정렬, 문단 앞·뒤 간격 0. 간격은 상자 위치로만 조절
- 섹션 제목·본문·소제목은 각각 별도 상자. 한 상자에 섹션 제목과 본문을 섞지 않음
- 목록은 글머리 기호 기능(`•`)으로 만들고 `-`, `*`, `•`를 글자로 쳐 넣지 않음
- 쪽 번호는 자동 쪽 번호 필드 사용

## 도식 규칙 (`diagram` 모드)

- 편집 가능한 PPT 도형·연결선으로만 그림. 이미지로 넣지 않음
- 글자는 키워드만. 문장 금지
- 강조할 차이만 그림. 설명용 장식·중복 라벨 제거
- Before와 After는 같은 구체성 수준, 같은 크기의 칸
- 면색·테두리·결과 표시 값은 `tokens-current-deck.md`의 도식 항목을 따름
  - 구조 비교형: Before·After 두 칸 같은 연회색 면
  - 순서도형: Before 구간 연회색 면, After 구간 흰 면 + 회색 테두리
  - 결과 표시: `X 코드` / `O 코드` (예: `X 409`, `O 202`)
- 순서도형은 시스템 축(예: 저장소 / 앱 / 서버)을 세로 점선으로 두고, 화살표 라벨은 두 축 사이 가운데, 화살표 바로 위에 둠
- 생략된 호출은 흐린 점선 화살표 + `생략` 라벨
- 공통 구간은 맨 위에 두고, 구간 이름(`공통` / `Before` / `After`) 옆의 `[ 상황 ]` 소제목은 같은 세로선에 정렬
- 같은 구간 안의 화살표는 같은 세로 간격으로 배치
- 강조색은 한 도식에 1~2곳만

## 차트 규칙 (`diagram` 모드)

- 회고 페이지 차트는 PPT 기본 차트(편집 가능)로 만듦. 이미지로 넣지 않음
- 값은 같은 프로젝트의 `03-1 결과` 또는 회고 페이지 본문에 있는 수치와 일치해야 함. 새 수치를 만들지 않음
- 감소율로 비교하는 지표는 한 계열 가로 막대, 감소율이 의미 없는 지표는 개선 전·후 두 계열 막대
- 색·글자 크기는 `tokens-current-deck.md`의 차트 항목을 따름

## 로고 규칙

- 기술 로고는 단색(333333) PNG, 0.32in 정사각
- 개요 페이지 왼쪽 아래에 핵심 기술 3개, 오른쪽에 기술 선택 이유 2줄
- 공식 로고가 없거나 사용 조건이 불분명하면 기술 이름 글자로 대신함

## 발표자 노트

- 모든 슬라이드 노트 첫 줄에 `[N페이지]` 표기. 페이지를 넣거나 빼면 함께 고침
- 면접 대비 근거: 측정 조건(환경·횟수·표본), 코드·테스트·문서 위치, 슬라이드에서 뺀 남은 한계
- 노트에 `undefined`나 빈 자리표시자가 남지 않게 확인

## 권장 중간 산출물

```text
[6페이지]
layout: L05
source_material: TS-01
title: ...
lead: ...
section_cause: ...
section_change: ...
section_result: ...
section_regression: ...
diagram: Before 키워드 / After 키워드
notes: ...
```

텍스트 박스가 자동으로 정확히 대응되지 않으면 슬라이드별 도형 번호와 역할을 별도 매핑한다.

## 간격·넘침 계산

렌더링 결과로 간격을 판단하지 않는다. LibreOffice로 PDF·이미지를 만들면 한글과 영문·숫자 사이에 빈칸이 더 들어가 PowerPoint와 줄바꿈이 다르게 나온다. 렌더링은 겹침·누락 같은 큰 문제를 찾는 데만 쓴다.

텍스트 상자 위치는 다음 순서로 정한다.

1. 문단마다 줄 수 계산
   - 글자 폭: Pretendard 글꼴 파일의 실제 글자 폭으로 문단 너비 계산
   - 사용 가능 폭: 상자 폭 − 안쪽 여백 − 글머리 들여쓰기(marL)
   - 줄바꿈: 띄어쓰기 단위로 끊음 (PowerPoint의 한글 기본 동작). 한 단어가 폭보다 길면 글자 단위로 끊음
2. 상자의 글자 높이 계산
   - 줄 높이 = 글자 크기 × 1.2 × 줄 간격 배수
   - 상자 안 글자 위끝·아래끝 위치 = 첫 줄 위치 + (전체 줄 수 − 1) × 줄 높이 + 글자 높이
3. `tokens-current-deck.md`의 간격 규칙(위 텍스트 아래끝 → 다음 텍스트 위끝)으로 다음 상자 위치 결정
4. 사용 가능 폭과 문단 너비 차이가 0.03in 안쪽이면 줄바꿈이 애매하므로, 상자 폭을 조금 넓히거나 문장을 줄임
5. 마지막 텍스트가 쪽 번호·슬라이드 아래끝(약 7.0in)을 넘지 않는지 확인

## 검증

- 바뀐 슬라이드 목록이 요청 범위와 같은지 원본과 비교
- 저장 후 파일을 다시 읽어 저장된 내용이 결과물과 같은지 확인
- 모든 슬라이드를 렌더링해 겹침·누락·이미지 깨짐 확인 (간격은 위 계산으로 판단)
- 가능하면 PowerPoint 화면 캡처로 최종 확인. 완료 보고에 PowerPoint로 확인했는지, 렌더링으로만 확인했는지 구분해 적음
- 숫자, 단위, 감소율의 원문 대조
- 서로 맞아야 하는 값 대조
  - 이력·목차의 `p.시작-끝` 범위 ↔ 실제 페이지
  - 발표자 노트의 `[N페이지]` ↔ 실제 페이지
  - 차트 값 ↔ `03-1 결과`·회고 본문 수치
  - 제목·본문·도식의 용어
- 원본 대비 의도하지 않은 도형·이미지·레이아웃 변경 확인
- 최종 PPT에서 텍스트를 다시 추출해 승인 원고와 대조
