# 마크다운 파일 저장 방식 (방식 2)

Notion 없이 `workspace/` 폴더의 md 파일만으로 소재를 관리하고, 필요한 파일을 AI에게 첨부해 작업하는 방식이다. Notion 방식(방식 1, `notion/schema.md`)과 같은 속성을 쓰므로 언제든 서로 옮길 수 있다.

## 언제 쓰는가

| | 방식 1 · Notion | 방식 2 · md 파일 |
| --- | --- | --- |
| 저장 위치 | Notion 데이터베이스 4개 | PC의 `workspace/` 폴더 |
| 필터·검색 | Notion 뷰 | 파일 맨 위 속성 블록(front matter) + 폴더 구조 |
| AI에 전달 | Notion 연결(커넥터)로 읽기 | md 파일을 첨부하거나 폴더를 연결 |
| 맞는 경우 | 소재가 많고 공고를 여러 개 관리할 때, 여러 기기에서 볼 때 | 빠르게 시작할 때, Notion을 쓰지 않을 때, 오프라인으로 관리할 때 |

두 방식 모두 같은 양식(`templates/`)과 같은 작성 기준을 쓴다. 다른 것은 저장 위치와 찾는 방법뿐이다.

## 폴더 구조

```text
workspace/
├─ _profile/                       지원자 공통 (최초 1회)
│  ├─ 00-profile.md
│  └─ 06-work-process.md
├─ <project-slug>/                 프로젝트마다 하나
│  ├─ 01-project-overview.md       프로젝트 레코드 역할도 겸함
│  ├─ 02-my-contribution.md        담당 기능이 여러 개면 02-my-contribution-2.md …
│  ├─ troubleshooting/
│  │  ├─ TS-01.md
│  │  └─ TS-02.md
│  └─ 04-retrospective-outcomes.md
└─ _jobs/                          공고마다 하나
   └─ <job-slug>/
      ├─ 07-job-posting.md         공고 원문과 요구 사항
      └─ 05-deck-plan.md           이 공고용 PPT 구성표
```

- 프로젝트 폴더는 `scripts/new-project.ps1`, 공고 폴더는 `scripts/new-job.ps1`로 만든다.
- `workspace/`는 `.gitignore`에 들어 있어 공개 저장소에 올라가지 않는다.

## 속성 블록 (front matter)

모든 양식 맨 위에 `---`로 둘러싼 속성 블록이 있다. Notion 데이터베이스의 속성과 1:1로 대응하며, 이 블록이 필터와 공고 매칭의 기준이 된다. 본문의 `식별 정보`와 값이 다르면 속성 블록을 먼저 고친다.

### 소재 파일 (00~04, 06)

| 키 | 값 | Notion 속성 |
| --- | --- | --- |
| `소재_ID` | `PROFILE`, `WORK-PROCESS`, `OVERVIEW-01`, `CONTRIB-01`, `TS-01`, `RETRO-01` | 소재 ID |
| `유형` | 이력·목차 / 작업 방식 / 개요 / 담당 기능 / 트러블슈팅 / 회고·성과 | 유형 |
| `프로젝트` | 프로젝트명. 이력·목차와 작업 방식은 비움 | 프로젝트 (관계) |
| `상태` | 자료 수집 / 초안 / 검증 대기 / 승인 / 보류 | 상태 |
| `한_줄_결과` | 공고 선별용 요약 | 한 줄 결과 |
| `역할` | 목록 | 역할 |
| `강점_태그` | 목록 (`references/tag-taxonomy.md`) | 강점 태그 |
| `영향_태그` | 목록 | 영향 태그 |
| `기술_태그` | 목록 | 기술 태그 |
| `기여_형태` | 직접 구현 / 공동 설계·구현 / 팀 전체 | 기여 형태 |
| `발생_성격` | 운영 발생 / 개발 중 발견 / 테스트 재현 / 잠재 위험 분석 / 해당 없음 | 발생 성격 |
| `증거_수준` | A / B / C / D | 증거 수준 |
| `정량_근거` | true / false | 정량 근거 |
| `회귀_확인_포함` | true / false (트러블슈팅) | 회귀 확인 포함 |
| `공개_가능` | true / false | 공개 가능 |
| `최종_검토일` | YYYY-MM-DD | 최종 검토일 |

`01-project-overview.md`에는 프로젝트 레코드 속성도 함께 둔다: `기간`, `팀_구성`, `내_담당_범위`, `프로젝트_상태`(수집 중 / 검증 중 / 활용 가능 / 보관), `공개_범위`.

### 공고 파일 (07)

| 키 | 값 | Notion 속성 |
| --- | --- | --- |
| `회사_직무` | `회사-직무` | 회사·직무 |
| `공고_URL` | 주소 | 공고 URL |
| `마감일` | YYYY-MM-DD | 마감일 |
| `상태` | 검토 / 지원 준비 / 지원 완료 / 종료 | 상태 |
| `요구_역할`, `요구_강점`, `요구_기술` | 목록 | 요구 역할·강점·기술 |

### 구성표 파일 (05)

| 키 | 값 | Notion 속성 |
| --- | --- | --- |
| `초안명` | `회사-직무-날짜` | 초안명 |
| `채용_공고` | 공고 폴더 이름 | 채용 공고 (관계) |
| `선택_소재` | 소재 파일 경로 목록 (예: `ody/troubleshooting/TS-01.md`) | 선택 소재 (관계) |
| `목표_페이지_수` | 숫자 | 목표 페이지 수 |
| `원본_PPT`, `결과_PPT` | PC 경로 | 원본 PPT, 결과 PPT |
| `상태` | 소재 선별 / 원고 작성 / 페이지 검토 / PPT 반영 / PowerPoint 확인 / 검증 완료 | 상태 |
| `확인_방법` | PowerPoint 화면 확인 / 렌더링과 줄 수 계산만 | 확인 방법 |
| `최종_검증일` | YYYY-MM-DD | 최종 검증일 |
| `확인_필요_수` | 숫자. 0이어야 검증 완료 | 확인 필요 수 |

## Notion 뷰 대신 쓰는 찾기

| Notion 뷰 | md 방식에서 찾는 법 |
| --- | --- |
| 프로젝트별 소재 | `workspace/<project-slug>/` 폴더 |
| 트러블슈팅 뱅크 | `workspace/*/troubleshooting/*.md` |
| 공고 매칭 가능 | 속성 블록이 `상태: 승인`, `공개_가능: true`, `증거_수준: A~C`인 파일 |
| 근거 보완 | `상태: 검증 대기` 또는 `증거_수준: D`인 파일 |
| 지원자 공통 | `workspace/_profile/` 폴더 |
| 지원 준비 공고 | `workspace/_jobs/*/07-job-posting.md` 중 `상태: 검토` 또는 `지원 준비` |

AI에게 맡길 때는 "workspace 폴더의 속성 블록 기준으로 `상태: 승인`인 트러블슈팅만 골라 줘"처럼 요청하면 된다. PowerShell에서 직접 찾을 때는 다음처럼 쓴다.

```powershell
Select-String -Path .\workspace\*\troubleshooting\*.md -Pattern '^상태: 승인' | Select-Object Path
```

## 단계별로 AI에 보낼 파일

폴더를 AI에 연결할 수 있으면 폴더째 연결하고, 아니면 아래 파일만 첨부한다. 매번 `SKILL.md`가 가리키는 기준 문서도 함께 보낸다 (스킬로 설치했다면 생략).

| 단계 | 보낼 파일 | 받을 결과 |
| --- | --- | --- |
| 프로필 | 이력서·자격증 등 원자료 + `_profile/00-profile.md`, `06-work-process.md` | 채운 프로필 파일 |
| 자료 정리 | 프로젝트 README·코드 경로·측정 자료 + 해당 프로젝트 폴더의 양식 | 채운 01~04 파일 |
| 공고 매칭 | `_jobs/<job>/07-job-posting.md` + 각 프로젝트 폴더의 소재 파일 (상태 승인) | `05-deck-plan.md`의 선택 소재 표와 페이지 구성 |
| 원고 작성 | `05-deck-plan.md` + 선택 소재 파일 + `_profile/` | 페이지별 원고와 노트 |
| PPT 반영 | 원고 + PPT 파일 | 수정된 PPT |

- 받은 결과는 같은 파일에 덮어쓰고 속성 블록의 `상태`와 `최종_검토일`을 고친다.
- 소재 파일 이름과 `소재_ID`를 바꾸지 않는다. 구성표의 `선택_소재`가 경로로 연결되기 때문이다.

## Notion으로 옮기기 (방식 2 → 1)

속성 블록의 키를 위 표의 Notion 속성에 그대로 넣고, 본문은 페이지 본문으로 붙인다. 반대로 Notion에서 md로 옮길 때는 페이지를 마크다운으로 내보낸 뒤 맨 위에 속성 블록을 채운다.
