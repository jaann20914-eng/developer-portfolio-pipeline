# 포트폴리오 레이아웃 명세

이 문서는 슬라이드의 정보 구조와 배치 역할만 정의한다. 글꼴, 크기, 굵기, 색상, 장식 스타일은 정의하지 않는다.

## 적용 우선순위

1. 사용자가 지정한 기존 PPT 레이아웃
2. 사용자가 승인한 페이지별 구성표
3. 이 문서의 기본 레이아웃

기존 PPT에 텍스트만 적용하는 작업에서는 도형의 위치, 크기, 슬라이드 수, 이미지 영역을 변경하지 않는다. 이 문서는 어떤 내용을 어느 영역에 넣을지 판단할 때만 사용한다.

## 공통 화면 구조

```text
┌────────────────────────────────────────────┐
│ 제목 영역                                  │
│ 페이지의 문제·주제·결과                    │
├────────────────────────────────────────────┤
│                                            │
│ 핵심 콘텐츠 영역                           │
│ 페이지 유형에 따른 흐름·비교·설명          │
│                                            │
├────────────────────────────────────────────┤
│ 근거 영역                                  │
│ 측정 조건·수치·한계·출처                   │
└────────────────────────────────────────────┘
```

## 공통 영역

| 영역 ID | 역할 | 필수 여부 | 배치 원칙 |
| --- | --- | --- | --- |
| `title` | 페이지의 실제 주제 또는 문제 | 필수 | 슬라이드 상단, 한 가지 메시지 |
| `lead` | 제목을 보완하는 한 줄 설명 | 선택 | 제목만으로 맥락이 부족할 때 사용 |
| `content-primary` | 가장 중요한 흐름·비교·결과 | 필수 | 시선이 먼저 닿는 중심 영역 |
| `content-secondary` | 원인·설계·보조 설명 | 선택 | 핵심 메시지보다 시각적 우선순위 낮춤 |
| `evidence` | 수치·테스트·측정 조건 | 필요 시 필수 | 주장과 가까운 위치에 배치 |
| `limits` | 한계·부작용·남은 과제 | 트러블슈팅에서 필수 | 결과와 분리하되 생략하지 않음 |
| `meta` | 기간·인원·역할·기술 | 필요 시 사용 | 본문 흐름을 방해하지 않는 위치 |

## 페이지 유형

### L01. 표지

목적: 지원자의 정체성과 포트폴리오 범위 전달

```text
[이름·직무]
[한 줄 소개]
[연락처 또는 링크]
```

- 프로젝트 상세 내용 배치 금지
- 장식보다 이름과 지원 직무 우선

### L02. 자기소개

목적: 개발 관점, 강점, 경험 범위 전달

```text
[자기소개 본문]
[핵심 강점]
[경험 또는 기술 범위]
```

- 문장형 서술 허용
- 이후 프로젝트에서 증명할 수 있는 강점만 제시

### L03. 프로젝트 개요

목적: 처음 보는 사람이 서비스와 담당 범위를 이해

```text
[프로젝트 한 줄 설명]
[배경 문제]        [서비스 해결 방식]
[주요 이용 흐름]
[기간·인원·담당 영역]
```

- 사용자 문제와 이용 흐름을 기술 스택보다 먼저 배치
- 팀 전체 기능과 직접 담당 범위 구분

### L04. 담당 기능

목적: 직접 맡은 기능의 동작과 설계 기준 전달

```text
[기능의 사용자 상황]
[1단계] [2단계] [3단계] [4단계]
[설계 핵심]
[직접 효과·근거]
```

- 단계가 실제 자료로 확인될 때만 흐름 사용
- 기술명은 해결한 문제와 연결

### L05. 트러블슈팅 진단

목적: 문제 상황과 해결 방향을 한 화면에서 전달

```text
[실제 문제 제목]
[문제 상황]
[진단] [전략] [적용] [검증]
```

- 행위자, 행동, 기대 상태, 실제 상태가 드러나는 문제 설명
- 네 항목은 각각 한 가지 판단만 포함

### L06. 트러블슈팅 전후 비교

목적: 구조 변경과 효과를 비교

```text
[기존 구조]              [개선 구조]
[처리 흐름]              [처리 흐름]

[직접 효과]
[정량 변화·검증 결과]
[영향과 한계]
```

- 기존 구조와 개선 구조의 구체성 수준 통일
- 전후 수치에 측정 대상과 조건 포함
- 성능 수치가 없는 사례는 허용·거부 결과나 상태 변화로 검증

### L07. 성과·회고

목적: 결과와 다음 프로젝트에 적용할 판단 원칙 정리

```text
[직접 구현 성과]        [프로젝트 전체 성과]
[배운 점]
[아쉬운 점·개선 방향]
[핵심 회고]
```

- 직접 성과와 팀 성과를 시각적으로 분리
- 배운 점을 추상적 감상보다 재사용 가능한 원칙으로 표현

### L08. 프로젝트 구분

목적: 프로젝트 전환 표시

```text
[프로젝트명]
[서비스 한 줄 설명]
[역할·기간]
```

- 다음 프로젝트의 핵심 맥락만 제시
- 앞 프로젝트의 성과 반복 금지

## 정보 밀도 규칙

- 한 페이지에 중심 메시지 하나
- 제목과 본문에서 같은 문장 반복 금지
- 텍스트 박스 수를 늘리기보다 문장 우선순위 조정
- 모든 섹션을 억지로 채우지 않고 해당 페이지에 필요한 영역만 사용
- 설명이 넘치면 페이지를 임의로 추가하기 전에 문장을 압축하고 사용자에게 분량 변경 확인
- 수치, 단위, 비교 대상, 한계는 공간 부족을 이유로 우선 삭제하지 않음
