# 개발자 포트폴리오 파이프라인

프로젝트 자료를 한 번 정리해 두고, 채용 공고에 맞는 소재를 골라 기존 PPT 레이아웃에 텍스트 초안을 만드는 재사용형 작업 구조다.

## 파이프라인

```text
README·코드·테스트·측정 자료
        ↓
프로젝트 개요 + 담당 기능 + 트러블슈팅 N건 + 회고·성과
        ↓
Notion 프로젝트·소재 데이터베이스
        ↓
채용 공고의 역량·기술·문제 유형과 소재 태그 대조
        ↓
슬라이드 구성표 → 페이지별 최종 문구 → 기존 PPT 텍스트 교체
```

핵심 원칙은 다음과 같다.

- 프로젝트마다 `개요 1건`, `담당 기능 1건 이상`, `트러블슈팅 N건`, `회고·성과 1건`으로 분리
- 트러블슈팅 하나를 독립적인 재사용 소재로 관리
- 사실, 직접 기여, 팀 성과, 측정 조건을 분리
- 확인되지 않은 값은 `확인 필요`로 유지하고 최종 PPT에서는 제거
- 공고에 맞춰 소재를 선별하되 없는 경험이나 수치를 새로 만들지 않음
- 최종 문구 작성 시 [포트폴리오 문구 작성 기준](references/portfolio-writing-guide.md)을 항상 적용
- 기준 문서의 원칙만 적용하고 예시에 나온 프로젝트 용어와 문구는 재사용하지 않음

## 폴더 구성

```text
portfolio-pipeline/
├─ SKILL.md                         Codex에서 파이프라인을 실행하는 스킬
├─ templates/                       사람이 작성하거나 AI에 전달할 입력 양식
├─ prompts/                         일반 AI에서도 사용할 단계별 프롬프트
├─ references/                      문구 기준·태그·PPT 적용 규칙
├─ design/                          레이아웃·디자인 토큰·교체형 디자인 옵션
├─ notion/                          데이터베이스 속성·뷰·페이지 템플릿
└─ scripts/new-project.ps1          새 프로젝트 입력 폴더 생성기
```

## 빠른 시작

### Codex 스킬로 설치

저장소를 내려받은 뒤 이 폴더 전체를 Codex의 skills 디렉터리 아래 `build-developer-portfolio`라는 이름으로 복사한다. `SKILL.md`만 떼어 옮기면 연결된 템플릿과 기준 문서를 읽을 수 없으므로 폴더 전체를 유지한다.

설치 후 다음과 같이 요청할 수 있다.

```text
$build-developer-portfolio를 사용해서 첨부한 프로젝트 자료를 개요, 담당 기능,
트러블슈팅, 회고·성과 소재로 정리해 줘. 확인되지 않은 내용은 확인 필요로 남겨 줘.
```

Codex가 아닌 AI에서는 `prompts/`의 단계별 프롬프트와 해당 프롬프트가 가리키는 `templates/`, `references/` 파일을 함께 전달한다.

### 1. 프로젝트 입력 폴더 생성

PowerShell에서 저장소 루트를 기준으로 실행한다.

```powershell
./scripts/new-project.ps1 -ProjectSlug "my-project" -ProjectName "프로젝트명"
```

`workspace/my-project/` 아래에 네 종류의 양식과 트러블슈팅 폴더가 생성된다.

### 2. 자료 정리

다음 순서로 작성한다.

1. `01-project-overview.md`: 서비스 배경, 사용자 흐름, 팀과 역할
2. `02-my-contribution.md`: 직접 맡은 기능과 설계 규칙
3. `troubleshooting/TS-01.md`: 문제 1건당 파일 1개
4. `04-retrospective-outcomes.md`: 직접 성과, 팀 성과, 회고

모르는 값은 추정하지 말고 `확인 필요`로 둔다. 원문, 코드, 테스트, 측정 결과의 경로를 함께 남긴다.

### 3. Notion에 저장

[Notion 스키마](notion/schema.md)에 따라 데이터베이스 4개를 만든다. 프로젝트 페이지 한 장에 모든 내용을 붙이지 않고, `포트폴리오 소재` 데이터베이스에서 개요·담당 기능·트러블슈팅·회고를 각각 독립 레코드로 만든다.

이 저장소에는 특정 사용자의 Notion 워크스페이스 주소나 데이터베이스 ID를 넣지 않는다. 실제 데이터베이스 생성은 사용할 Notion 상위 페이지를 정한 뒤 스키마 순서대로 수행한다.

### 4. 공고별 소재 선별

채용 공고를 `채용 공고` 데이터베이스에 저장하고, [공고별 소재 선별 프롬프트](prompts/02-match-job.md)를 사용한다. 결과에는 선택 이유와 제외 이유가 함께 남아야 한다.

### 5. PPT 초안 생성

기존 PPT, 승인된 소재, 희망 페이지 수를 전달하고 [PPT 초안 프롬프트](prompts/03-build-deck.md)를 사용한다.

1. 먼저 페이지별 텍스트 원고 생성
2. 페이지 단위 검토와 승인
3. 승인본을 기존 PPT 레이아웃에 텍스트만 반영
4. 렌더링 후 잘림·겹침·누락 확인

PPT의 정보 배치는 [레이아웃 명세](design/layout-spec.md), 글꼴·크기·간격·색상 값은 [디자인 토큰](design/design-tokens.md)에서 관리한다. 향후 교체할 시각 스타일은 [디자인 옵션](design/design-options.md)에 별도로 등록한다.

기존 PPT를 사용하는 경우 `preserve-existing`이 기본값이다. 사용자가 디자인 변경을 명시적으로 요청하기 전에는 디자인 토큰이나 옵션을 기존 PPT에 적용하지 않는다.

## 권장 운영 규칙

- `원자료 → 소재 초안 → 승인 → PPT 반영`의 상태를 건너뛰지 않음
- 같은 개념의 용어는 프로젝트 용어표에서 하나로 고정
- 회사마다 문장을 억지로 바꾸기보다 공고에 맞는 소재 조합을 먼저 변경
- 민감 정보, 자격 증명, 실제 사용자 데이터는 Notion과 공개 저장소에 저장하지 않음
- 개인 프로젝트 자료와 실제 PPT 파일은 공개 저장소 밖에서 관리

## 공개 저장소로 배포하기 전

- 예시 데이터에 개인정보·회사명·비공개 링크가 없는지 확인
- `workspace/`, 원본 PPT, 측정 원본 등 개인 자료가 커밋되지 않았는지 확인
- 저장소 라이선스 선택 후 `LICENSE` 추가
- Notion 템플릿 공개 복제 링크를 만들었다면 README에 연결

현재 패키지는 라이선스를 임의로 선택하지 않았다. 공개 배포 전 MIT, Apache-2.0 등 원하는 조건을 정해야 한다.
